# Пересмотр при новых данных

Новые данные: $ARGUMENTS

1. Зарегистрируй новое сведение: источник — `python tools/strateg.py source add …`, утверждение — строка в `evidence.jsonl` (или `evidence add`). Вид укажи честно: результат измерения — `fact`, оценка — `forecast`.
2. Определи, что оно затрагивает:
   - найди прежние утверждения на ту же тему: `python tools/strateg.py search "<ключевые слова>"`;
   - для каждого затронутого: `python tools/strateg.py impact <E-id>` — покажет строки документов и решения, которые на него опираются.
3. Для каждого затронутого утверждения выбери одно:
   - **подтверждено** — добавь новый источник в его `sources`;
   - **опровергнуто или устарело** — `python tools/strateg.py revoke <E-id> --reason "…"` и новое утверждение взамен. Текст старого не стирай.
4. Обнови только затронутые места документов: замени ссылки на отозванные утверждения, пересчитай числа через субагента `analyst` (скрипт в `analysis/` меняется, старый результат остаётся в истории git), перепиши выводы, которые из этих чисел следовали.
5. Проверь, не изменился ли выбор: если новое значение пересекает «границу решения» из вариантов или стратегии — скажи об этом человеку первым делом и вынеси вопрос через `gate ask`.
6. `python tools/strateg.py check` — ссылок на отозванные утверждения не осталось. `python tools/strateg.py decisions due` — какие решения пора пересмотреть.
7. Отчёт человеку: что пришло; какие утверждения отозваны и заменены; какие разделы и числа изменились (было → стало); меняется ли рекомендация; какие решения требуют внимания.
8. `python tools/strateg.py log note "Пересмотр: <что и почему>"`.
