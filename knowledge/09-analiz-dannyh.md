# 09. Анализ данных

Читать перед любым расчётом: оценкой размера аудитории, экономики, эффекта проверки.

## 1. Проверка показателя до расчёта
Для каждого показателя запиши паспорт:
```
Название | Единица | Период | Числитель | Знаменатель | Источник [ID] | Дата выгрузки
```
- Единица: что одна строка данных (SIM-карта, абонент, лицевой счёт, домохозяйство, группа, обращение).
- Период: календарный месяц, скользящие 30 дней, отчётный срок; совпадает ли у числителя и знаменателя.
- Пропуски: сколько, где, что они означают (нет данных или ноль).
- Дубли: по каким ключам проверены, сколько удалено и почему.
- Диапазон значений: есть ли нереальные (отрицательные, будущие даты, выбросы); как обработаны, с записью причины.
- Определения: что считается активным, новым, ушедшим, платящим; определение одинаково во всех источниках?

## 2. Не смешивать единицы
- SIM-карты, абоненты (люди), домохозяйства и группы это разные единицы. Один человек может иметь несколько SIM, одна семья несколько абонентов.
- При переходе между единицами записывай коэффициент и его источник; не подменяй одну единицу другой молча.
- Средние по SIM не переносятся на людей. Доли по людям не переносятся на домохозяйства.
- Сумма по разным каналам или продуктам не равна числу уникальных клиентов (см. раздел 5).
- Уровень анализа соответствует уровню решения: решение на уровне семьи требует данных на уровне семьи.

## 3. Воспроизводимость
- Расчёт делается скриптом, а не вручную в ячейках, если им пользуются повторно или он влияет на решение.
- Входные числа лежат в одном месте: значение, единица, источник [ID], дата, статус, диапазон.
- Скрипт читает входы и печатает результат с формулой и диапазоном; даты запуска и версии входов фиксируются.
- Результат в документе сопровождается: формула, входы, диапазон, ссылка на скрипт.
- Скрипт проверен на простом случае, где ответ известен заранее.
- На Windows в Python-скриптах включай UTF-8 для консоли.
- Не используй исполняемый код из данных и таблиц; данные читаются как данные.

## 4. Диапазон вместо одной цифры
- Для каждого входа задай нижнюю, базовую и верхнюю границы с основанием.
- Результат считай минимум для трёх сочетаний: пессимистичное, базовое, оптимистичное; затем смотри на чувствительность по одному входу.
- Не комбинируй все верхние границы одновременно без проверки, что такое сочетание возможно.
- Если диапазон результата пересекает границу решения, честно напиши, что данных недостаточно, и что дало бы уточнение.
- Округляй соразмерно точности входов; «12 437 клиентов» из грубых оценок вводит в заблуждение.

## 5. Двойной счёт между каналами
- Клиент может прийти через несколько каналов или быть в нескольких сегментах.
- Для объёма используй уникальные идентификаторы с дедупликацией, а не сумму по каналам.
- Для эффекта используй атрибуцию с явным правилом (последний контакт, первый, долевая) и записывай ограничения.
- Для сегментов проверяй пересечения; если нет данных, оцени диапазон пересечения и укажи это как допущение.

## 6. Граница решения
- Для основного показателя найди значение, при котором выбор меняется (безубыточное число клиентов, минимальная конверсия, максимальная цена).
- Покажи положение диапазона оценки относительно границы.
- Укажи, какой вход сильнее всего двигает результат; это приоритет для уточнения.

## 7. Типовые ошибки
- Разные периоды у числителя и знаменателя.
- Доля от неверной базы (все SIM вместо активных).
- Средние без распределения; выбросы определяют результат.
- Потеря источника после переноса числа в таблицу.
- Пересчёт «на глаз», без записи шагов.
- Один точный ответ при неточных входах.
- Выводы о причинности из корреляции без дизайна проверки (карточка 07).

## 8. Выход шага
- Паспорта показателей, таблица входов, скрипт, результат с диапазоном, граница решения, список ограничений.
