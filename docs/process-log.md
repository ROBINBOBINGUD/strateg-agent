### 19:10–19:25. Архитектура (решения)
1. **Одна папка — четыре раздельных слоя:** постоянные инструкции (`AGENTS.md`, `.claude/`), методические знания (`knowledge/`), материалы и результаты проекта (`projects/<id>/`), состояние задачи (`state.json`, `journal.jsonl`, `costs.jsonl`). Плюс память между проектами (`memory/`).
2. **Правила в `AGENTS.md`, а не в `CLAUDE.md`:** так папка читается и Claude Code, и Codex, и Cursor. `CLAUDE.md` только импортирует его.
3. **Состояние ведёт детерминированный CLI, а не модель:** шаги, ожидание решения человека, журнал и расходы меняются командами `tools/strateg.py`. Модель не может «забыть» обновить состояние незаметно — хук запрещает править эти файлы руками.
4. **Реестр доказательств:** источники `S-…` и утверждения `E-…` с видом (факт, гипотеза, прогноз, допущение, синтетика). `check` проверяет, что каждая ссылка в тексте существует и не отозвана; `impact` показывает, что затронет новое сведение.
5. **Маршрутизация:** сильная модель — синтез, Sonnet — поиск и расчёты, Haiku — модельные респонденты, CLI — всё, что можно проверить без модели.
6. **Три решения человека:** подтверждение постановки, выбор направления, приёмка. Между ними агент работает сам.
7. **Защита правил:** хук блокирует правку инструкций; хук проверяет текст источников на встроенные команды.

### 19:14–19:25. Первые запуски и найденные ошибки
- **Пробный запуск** (`claude -p`, Haiku, 7 секунд, 0,01 USD): хук старта, 12 skills и 4 субагента видны агенту.
- **Находка 1.** В новой папке `claude -p` игнорирует `permissions.allow` из `.claude/settings.json`, пока человек не подтвердил доверие к папке. Решение: для неинтерактивных запусков разрешения передаются флагами (`runs/run.sh`); в README — шаг «подтвердите доверие».
- **Находка 2.** `--setting-sources project,local` не отключает личный `~/.claude/CLAUDE.md` пользователя. Решение: в `CLAUDE.md` проекта добавлена строка о том, что в папке действует только процесс из `AGENTS.md`.
- **Заход 1 (постановка):** 2 минуты, 0,88 USD (Opus 5.5). Агент создал проект `family-multisim`, скопировал материалы, составил постановку и задал два блокирующих вопроса с вариантом по умолчанию для каждого.
- **Ошибка агента и исправление правил.** Агент трижды пытался выполнить составные команды (`cd … && python …; cat …`, встроенный Python) и получил отказ по разрешениям. Он сам перешёл на одиночные команды, но это лишние ходы. В `AGENTS.md` добавлено правило: команды по одной, без `cd` и `&&`, файлы читать инструментами среды.
- **Ошибка в моём хуке, найденная агентом.** На втором заходе `check` показал запись расходов без поля времени. Агент не стал править `tools/` (это запрещено правилами и хуком), а записал `log error` с точным указанием файла. Исправлено человеком-разработчиком: `stop_cost.py` теперь передаёт `ts`. Это пример того, как работает разделение «агент не меняет свои инструменты» и «ошибки не замалчиваются».
- **Автотесты хуков** (`tools/tests/test_hooks.py`, 7 тестов): защита правил и состояния, журнал, обнаружение встроенных команд в источнике на русском и английском, отсутствие ложных срабатываний на обычном тексте, учёт стоимости без двойного счёта.
- **Codex, второе задание:** независимое ревью репозитория глазами инженера жюри (соответствие команд в инструкциях коду CLI, хуки на macOS и Linux, README), без права менять файлы.

### 19:20–19:47. Независимое ревью Codex и правки по нему
Промпт ревью (`runs/codex-review-prompt.txt`): «Ты независимый рецензент, инженер жюри… проверь, запустится ли репозиторий по README на чистой машине Windows и macOS/Linux и согласованы ли инструкции с кодом… Ничего не изменяй… Каждое замечание — файл:строка, что не так, как исправить».

Codex (gpt-6.2-sol, high) проверил репозиторий во временных копиях, запустил тесты и вернул 3 критичных, 10 важных и 4 малых замечания. Вердикт был отрицательным: «без помощи член жюри не пройдёт README на обеих платформах». Что исправлено:

| Замечание Codex | Исправление | Кто |
|---|---|---|
| На macOS и Linux с одним `python3` быстрый старт и хуки не работают | хуки запускаются через `tools/hooks/run.sh`, который сам находит Python 3.10+; README даёт команды для двух платформ | Claude |
| Защита правил закрывает только инструменты правки; через оболочку правила можно переписать | хук проверяет и команды Bash и PowerShell; разрешён запуск только скриптов из `projects/*/analysis/`; в README честно сказано, что это не песочница | Claude |
| `step done` принимает несуществующий файл и закрывает шаг из любого статуса; повторный `gate answer` падает | CLI проверяет переходы, наличие файлов результата и открытый вопрос; повторный ответ безвреден | Codex |
| `check` пропускает ссылки неверного формата, ссылки в блоках кода считает настоящими, не ловит синтетику без пометки | разбор учитывает разметку, неверные маркеры — ошибка, абзац со ссылкой на синтетику обязан содержать слово «синтетика», основания решений проверяются | Codex |
| Блокировка по таймауту пускает запись без владения; выдача номера идёт вне блокировки | весь цикл «прочитать, изменить, записать» под блокировкой; таймаут — ошибка с просьбой повторить | Codex |
| Оценка хука может затереть точную сумму захода | точная запись имеет приоритет над оценкой | Codex |
| В журнале и сырых ответах есть локальные пути | журнал пишет относительные пути; сырые ответы лежат в `runs/raw/` вне git, в `runs/` — обезличенные сводки | Claude и Codex |
| Шаблоны встроенных команд дают ложные срабатывания | шаблоны сужены, добавлены отрицательные тесты | Claude |

Результат: 30 автотестов (19 для CLI, 11 для хуков), все зелёные. Первая же проверка исправленным `check` нашла в документе вариантов ссылку неверного формата `[E-023, гипотеза]`, которую прежняя версия пропускала.

Не исправлено и записано в ограничения: активный проект один на копию репозитория (два сеанса в одной папке могут писать в журнал друг друга); хуки не проверяют содержимое скриптов расчёта.
